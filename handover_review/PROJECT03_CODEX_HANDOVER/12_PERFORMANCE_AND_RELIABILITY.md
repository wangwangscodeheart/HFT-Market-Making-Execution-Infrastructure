# 性能、并发、可靠性与工程红线

目前没有本项目吞吐、P99.9、抖动、长稳或生产性能数字。参考模型/单元测试/CTest 总用时不能替代性能测量。下述是已保留的目标和验收方法，不是成果。

## 技术目标与进入条件

高性能关注 cache locality、memory layout、预分配、避免分配、CPU cycles/IPC、分支、NUMA、编译优化；低延迟关注分段/端到端、P50/P95/P99/P99.9、jitter和尾部归因；并发关注 Single Writer、ownership、event loop、有界队列、背压、atomic ordering、亲和与安全退出；可靠性关注检测、kill、会话恢复、对账、幂等、journal/snapshot、确定回放和优雅降级。

不为了展示技术盲目引入 lock-free、对象池、DPDK、AF_XDP、io_uring、多线程或分布式服务。先正确、测试、建立基线，再证明优化收益。每项技术说明解决什么问题、收益、复杂度、维护成本和失败边界。C++17 仅在明确兼容证据后重新评估；当前 C++20 不悄悄降级。

## 原 M0 测量和可靠性方法

## 12 性能与可靠性验收方法

### 12.1 先定义测量边界

| 指标 | 起点与终点 | 解释限制 |
|---|---|---|
| 行情归一化延迟 | SDK 回调或本地报文接收至事件入队 | 普通 SDK 回调不等于网卡硬件接收时间 |
| 排队延迟 | 入队至核心开始处理 | 与模块纯计算时间分别报告 |
| 策略决策延迟 | 读取有效行情至产生报价意图 | 包含的库存与计算步骤固定 |
| 风控延迟 | 开始检查至批准或拒绝 | 成功与失败路径分布分开 |
| 决策至发送 | 意图生成至 SDK 调用或本地发送边界 | 标明是否等待持久化与网关队列 |
| 回报处理延迟 | 回报接收至 OMS 和账本处理结束 | 查询和重复回报另列 |
| 行情至委托端到端 | 本地行情接收到本地发送边界 | 不称为交易所撮合延迟 |
| 外部确认延迟 | 本地发送至关联确认接收 | 混合网络、柜台及外部处理，不能凭此拆出每一段 |

先用 Linux 单调时钟建立跨线程可解释基线，记录具体 clock ID、分辨率与读取开销；CLOCK_MONOTONIC_RAW 可作为本地性能测量候选。交易日与展示时间使用独立墙钟语义。[S28] TSC、RDTSCP 或硬件时间戳须在测量开销、序列化、CPU 迁移、频率和时钟域问题有证据后再采用。

行情原始时间戳与本地时钟未验证同步时，两者相减只能作为带时钟偏差的观测量，不能当作精确单向网络延迟。行情年龄保护至少使用本地单调接收时间，并结合会话、心跳或其他可用健康信号；没有更新也可能只是没有市场变化，因此暂停应显示为保守陈旧保护，不伪称已证明上游丢包。

### 12.2 负载与统计方法

微基准、模块基准、端到端、压力、故障和长稳测试分别交付。使用同一输入与配置比较优化前后，报告 P50、P95、P99、P99.9、最大值、样本数和丢弃数量；不把多个阶段的 P99 相加作为端到端 P99。

压力测试同时设计 open-loop 与 closed-loop。前者按计划时刻投放，包含排队与过载；后者等待完成再推进，可用于受控功能或并发窗口测试，但可能掩盖停顿。Coordinated Omission 指负载或采样在系统停顿期间一并停下来，从而遗漏本应经历等待的请求。wrk2 作者文档提供这种测量偏差的说明，项目只借鉴方法，不将 HTTP 工具直接当成 CTP 性能证明。[S27]

负载生成器保存计划、实际投放与完成时间，分别报告生成器自身落后、入场拒绝、系统丢弃及未完成请求。直方图工具不会自动修正错误的负载设计；如使用 HdrHistogram 的具体移植版本，需核对其线程安全与校正接口并锁定版本。[S25]

建议起始统计方案：每个测点先预热，正式测量至少 5 个独立进程运行；测 P99.9 的高事件量场景以每次至少 100 万样本为目标，并同时给出尾部样本量与运行间差异。100 万样本只意味着最末 0.1% 约 1000 个样本，不是置信度保证。低频仿真结果不足时明确说明，不能补造尾分位。

运行记录必须包含 CPU 型号与核心拓扑、内存、NUMA、宿主或虚拟化信息、内核、编译器、构建 SHA、优化选项、CPU 亲和、负载形态、订阅范围、预热、持续时间、运行次数、时钟及直方图精度。perf 采样用于解释热点与尾延迟，Sanitizer 构建用于正确性，二者结果不冒充普通 Release 延迟。

### 12.3 技术优化进入条件

先确定瓶颈，再考虑布局、预分配、批处理、SPSC、亲和与缓存行隔离。每项优化必须给出相同负载下的收益、尾延迟变化和复杂度。对象池要说明容量耗尽策略；SPSC 要证明生产者与消费者唯一；批处理要说明等待带来的尾延迟；NUMA 要有多节点机器和证据。DPDK、AF_XDP、io_uring 不作为首版必做项。

M0 不承诺纳秒或微秒数值。M3 的通过条件是提供可复现基线、瓶颈证据和至少一项经测量成立的改进，或明确证明某项优化无收益并保留更简单实现。固定硬件与负载后再冻结项目 SLO；任何绝对目标必须与真实基线分开。

### 12.4 可靠性硬门槛

自动化测试至少覆盖重复成交、超量成交、撤单与成交竞态、撤单拒绝、回报乱序与迟到、未知订单、风控绕过、今昨仓冻结、行情陈旧、序列缺口、断线对账、跨日、有界队列满、日志失败和安全关闭。C++ 核心适用的单测、性质测试和本地集成测试进入 CI；解码器增加畸形输入与模糊测试。

关闭时先停止新报价，继续回报处理和必要撤单；无法在截止时间确认的外部订单进入待对账记录，持久化后退出，不能显示为“全部关闭成功”。对长期运行，先安排本地 24 小时稳定性试验，记录内存增长、队列水位、账本不变量与恢复结果；这是计划，不是已完成测试。

## 正式架构测点与容量（V1.1）

## 16 性能测量 可观测性与容量

### 16.1 测点契约

| 测点 | 所在边界 | 解释 |
|---|---|---|
| t0 | 行情回调或本地报文进入适配器 | 不是未经确认的网卡接收时间 |
| t1 | 核心开始处理该行情 | t1−t0 包含归一化与排队，子段可另拆 |
| t2 | 报价意图产生 | 策略决策完成 |
| t3 | 风控与预占完成 | 成功、拒绝分开统计 |
| t4 | 对应发送意图达到持久化边界 | 落盘等待不能从端到端指标中删掉 |
| t5 | 领取后实际调用发送接口 | 同时记录 claim 时刻和门闩 epoch |
| t6 | 关联订单或成交回报进入适配器 | 订单确认和成交不是同一个指标 |
| t7 | 该回报的 OMS 与账本处理完成 | 回报排队和纯处理可分开统计 |

每个直方图记录单位、范围、精度、样本数和溢出。P99.9、最大值、吞吐、未完成、拒绝、丢弃、队列水位、日志积压、gate 状态与恢复进度都按 runId 查询；不把多个阶段 P99 相加作为端到端 P99。

StepHarness 的逻辑时延与 RuntimeRunner 的物理时延分别报告。微基准、模块、端到端、压力、故障和长稳测试各有入口；外部公网或仿真延迟不冒充核心计算性能。时钟、编译器、CPU、内核、亲和、预热、次数和原始数据方法继承 M0 验收要求。

压力负载采用独立计划时刻的 open-loop，并保留实际投放与完成时刻、生成器落后和丢弃计数，避免停顿时同时停止投放造成 Coordinated Omission。closed-loop 另用于受控并发窗口和功能验证。M1 不冻结绝对纳秒目标，M3 在固定硬件和负载后才审定 SLO。

### 16.2 容量与内存

活动订单、待发效果、待撤动作、成交去重、隔离区、恢复缓存、队列、日志磁盘与 UI 帧都有容量和长度上限。配置中区分数量单位、字节与时间；M1 资源预算 ADR 给出初始值及推导，不用“足够大”代替耗尽策略。

小容量测试从 2 或 4 个槽位等容易穷尽的边界开始，证明满、空、关闭与并发唤醒行为。达到终态不代表马上可以删除全部身份；历史保留和墓碑释放必须与重传及恢复能力一致。

先测布局、复制与动态分配成本，再讨论预分配、缓存行、批处理、亲和或 SPSC；NUMA、DPDK、AF_XDP 和 io_uring 不进入 M1 前置。每项优化均需保留正确性、容量、关闭和过载测试，不为了展示技术增加线程或自定义内存回收。

## 交付红线

- 不忽略 UB、数据竞争、对象生命周期、回调借用指针、所有权、内存序和关闭依赖；平台、编译器/ABI/OS 假设必须写明。
- 所有容量有单位、来源和耗尽策略；关键回报不能静默丢弃；非交易观测允许有界降采样。
- 文件 write/flush 不等于 fsync 成功；完整可读前缀不等于崩溃前已同步；无本地—外部原子事务或端到端 exactly-once 承诺。
- 错误、未知与故障证据保留；超时不等于失败；重连不等于恢复；kill 不等于撤净；终态不等于账本完整。
- 运行/回放相同业务版本、参数和已排序输入应有相同决定和摘要；不要求不同机器物理延迟相同。
- 微基准、模块、端到端、压力、故障、长稳分别入口；新测量记录硬件/内核/编译器/选项/负载/预热/次数/统计/时钟/样本数/丢弃/未完成。
- open-loop 留计划投放与实际完成，解释 Coordinated Omission；closed-loop 不冒充停顿期间负载。直方图不能补救错误负载设计。
- 真实 CTP/SimNow 的网络与柜台耗时不冒充我们自己的核心性能；厂商宣传、旧项目数字和 Java 工具数字均不迁移为本项目结果。
- 真实故障、保护效果和恢复耗时必须实际运行后登记；本地模拟、规范夹具和真实源始终有 provenance。

## M1A 已知性能限制

候选 copy/validate/swap 每步复制业务状态并检查不变量，使用标准 map/vector 和动态分配。这是公开的正确性优先实现取舍，尚未测量，不是“高频性能已达标”。LSan 环境受阻必须单列，ASan/UBSan 成功不自动证明无泄漏。真正并发测试和 TSan 适用范围在 M1C，文件故障在 M1D，长稳仍待后续授权。
