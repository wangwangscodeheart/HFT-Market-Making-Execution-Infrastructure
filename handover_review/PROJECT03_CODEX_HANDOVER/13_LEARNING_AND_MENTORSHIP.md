# 学习背景、带教与解释标准

用户是软件工程本科生，既往自述 28 届、目标直接就业和买方 C++ 系统开发，不走量化策略研究路线。此处只保留与项目教学有关的背景，不从旧年级信息推断当前课程或时间安排。

## 教学目标

金融基础较弱，熟悉的是自己项目中的交易逻辑。应从宏观真实市场→机构关系与权限→业务链路→事件与状态→C++机制→源码→测试/调试逐渐推进。不能默认已经理解交易日、今昨仓、开平、保证金、柜台和交易所的区别。

解释要专业、通俗、有深度；先说明“为什么会遇到这个问题”，再把术语翻译成工程含义，最后看实际文件、状态变化和失败路径。学习目标是能够独立实现、调试、优化、维护和讲解，不是背 AI 生成说明。

## 每模块的带教交付

| 内容 | 必须能回答 |
|---|---|
| 场景与业务 | 市场为何要求它；账户/品种/接口的适用边界 |
| 源码 | 输入/输出、拥有的数据、调用顺序、生命周期、失败路径 |
| 设计取舍 | 正确性/性能/可靠性/维护成本的代价，何时重评 |
| 测试 | 具体输入、期望、实际、反例、复现命令；模型与实现分开 |
| 调试 | 断点/日志/状态检查，至少能复现一个失败并解释修正 |
| 面试 | 能准确介绍已有能力，明确未实现限制，准备不同问法的追问 |

训练可以用一个小修改、一次失败路径调试或一个问题验收，不做无休止考试。面试练习偏好一次一道题、点评后下一题；实现任务不应频繁停下来要求重复批准已授权内容。

## 最终应独立讲清

为什么选中国期货/RB、为什么 CTP、行情来源与有限档位、报价如何生成、风控怎么预占、OMS 为何四维/终态仍可记账、网关怎样发送/归并、断线未知为何不能重发、今昨仓和资金如何核对、线程模型的理由、perf定位、P99.9样本和偏差、故障注入、公开事实与模拟结果的差别、距离生产还差什么。
