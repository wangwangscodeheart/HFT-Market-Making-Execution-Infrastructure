# M1A 执行与接管审查计划

本文件依据 V1.1 §17.2 及用户启动要求整理，不授予本轮编码权限。当前已有未验收候选，接管时先审查/复现，再在已授权 M1A 范围内按用户具体任务处理，不能假设从空仓库开始。

## M1A 定义（原文）

### 17.2 M1 分步交付

| 步骤 | 最小交付 | 放行标准 |
|---|---|---|
| M1A 类型与业务内核 | 身份、合约、四桶、状态机、风险预占及 StepHarness | A01、A04–A08，O01 至 O09、P01 至 P06 的业务实现测试成立 |
| M1B 本地闭环 | 简化策略、LocalSim、普通限价与撤成场景 | A02、A03，完整报价轨迹及独立本地查询证据成立 |
| M1C 运行时 | 有界队列、四线程职责、gate、超时与暂停 | A10、A11、K01 至 K07 的实际并发版本；回报溢出同步关 gate |
| M1D 日志与回放 | 顺序日志、持久化发送约束、禁外发 ReplayRunner | A12、J01 至 J07 的实际 Writer 版本；未知发送不重发，恢复证书先落盘 |
| M1E 基础工作台 | 独立 WebBridge、快照与命令契约、基础页面 | A16；展示停止状态、前缀、证据缺项和资金覆盖，UI 断开不影响回报 |
| M1F 交付复核 | 最小故障脚手架、关闭、文档和干净构建 | A15、A18 基础及 Q01 至 Q09 本地版本；覆盖不足保持暂停 |

M1A 与 M1B 可先用纯内存测试材料验证业务；只有 M1D 验收后，运行演示才可以宣称具有本报告的持久化发送保证。M1 允许单进程 LocalSim 重启后丢失外部模型，但必须说明该限制，不能标记 A17 完整通过。

## M1A 的必须通过项

A01、A04～A08，O01～O09，P01～P06 的业务适用部分；针对真实类，不能只复制参考模型。每个输入给出期望状态/资源、错误、实际状态与可复现命令。事务失败、超量/重复/迟到、撤成竞争、未知、跨日阻断、容量和算术边界均需可检查。

## 复现命令（不是本次交接已经执行的命令）

在 `implementation/m1a_candidate/project03` 下：

```bash
cmake -S . -B build/handover-debug -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/handover-debug --parallel 2
ctest --test-dir build/handover-debug --output-on-failure
./build/handover-debug/p03_tests
./build/handover-debug/p03_m1a_demo
```

需要 C++20 编译器、CMake≥3.20 和本机构建工具。当前候选测试仅依赖标准库，无需 CTP 或网络。历史构建使用 GCC 13.3.0/CMake 3.31.6；不保证所有编译器已经验证。新日志另存，不覆盖原始 evidence。

## 严禁提前实施

M1A 不包含策略自动报价与 LocalSim 对端（M1B），真实线程/队列/gate（M1C），Journal/持久化发送/恢复证书（M1D），WebBridge/前端（M1E），完整故障与恢复（M1F/M4），CTP/SimNow/SMDP（M2）。模型中的类型或负例也不授予这些模块实现权限。能力未实现必须 NotImplemented/Blocked，不返回成功空实现。

## 提交验收必须包含

实际源码与目录说明；构建/测试命令；逐例清单与原始输出/失败统计；实现与未实现边界；V1.1 对应；问题、取舍和偏差。每模块附业务语义、源码、测试、调试及面试解释。未经用户正式验收，不把 M1A 标为 Accepted，不自动进入 M1B。
