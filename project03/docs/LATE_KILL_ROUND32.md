# 第三十二轮：停机后迟到成交、终态缺项与重复 Stop

日期：2026-11-07。

## 修正重复 Stop 的活动量判定

原 withdraw 以 held = H+P+V 判断是否需要再次撤单。若已收到撤单终态但成交明细未到，订单可能只有 H；它保留风险，却没有仍可撤的委托量。重复 Stop 会再次发出 RequestCancel，被核心以 InvalidInput 拒绝。

现在仅对 P 或 V 仍大于零且不在待撤/未知撤单状态的订单尝试撤单。纯 H 占用保留，不因停止或重复停止释放，也不再次当作活动委托撤销。未知/仍可能活动的风险仍按原规则处理。

## 三组 C++ 验证

新增独立七帧 `--late-fill` 场景：每侧三手报价；买侧成交一手但暂扣推送；在普通额度耗尽后用收尾路径 Stop；重复 Stop；迟到推送入账；查询重放；重复推送。首个 Stop 的精确累计终态使买单 B/H/P/L/V 为 `0/1/0/2/0`，重复 Stop 只有一次 Kill 调用，不重撤终态单。推送补齐后数量为 `1/0/0/2/0`。

H 变为 B 前后核心资金需求均为 102 个本地模型单位。前者保留缺项风险，后者归属已记账持仓，不因 Kill 变成零。整个收尾阶段核心保持 Killed，容量停报不解除，最终两侧今多均为一手。

另两组回归验证：先查询补齐，再接原推送，推送返回 Duplicate；对端已经全部成交而核心尚未知时，撤单拒绝不能当作未成交证明，原 P 占用保留，直到实际成交到达。

新增测试逐帧重放比较核心摘要、数量分区和收尾标记，并验证之后市场输入仍被拒绝。

## 可核验回报字段

导出程序新增 CancelReport.cancel_state、TerminalReport.terminal_kind/exact_quantity，以及 TradeReport.trade_id/channel/source。页面调用表展示撤单响应或精确累计终态，详情区展示实际调用与回报摘要，能对照先收到终态、后收到明细的证据顺序。

这是诊断投影，不是完整厂商报文或可持久恢复的事件编码。没有把推送/查询通道纳入经济成交身份，不复制记账。

报价页增加第七个“Kill 后迟到成交 / 终态 / 去重”场景。Node DOM 检查覆盖 H 占用、重复 Stop 单调用、迟到入账、查询通道、精确终态证据、去重和来源切换。构建脚本新增 quote-late-fill.json，带新增标记的构建必须包含该文件，原始产物共 32 项。

证据目录：`evidence-local/2026-11-07-late-kill-debug`、`evidence-local/2026-11-07-late-kill-release`。

## 限制

最终 MSVC Debug / Release 各 221 项测试、27032 次断言通过，零失败/跳过。四方测试清单一致、八项证据负控和页面 Node 逻辑检查通过；十二份导出诊断逐字一致，当前页面使用本轮 Release 数据。原生浏览器布局尚未验证。

接口夹具与独立 LocalSimulator，仅验证显式暂扣回报的本地组合。不是生产丢包检测、真实柜台撤单语义或历史轨迹。收尾、队列和状态仍在有限内存中，无后台时钟、并发、耐久日志、跨进程恢复、原生浏览器布局验收、Linux 或真实性能验证。
