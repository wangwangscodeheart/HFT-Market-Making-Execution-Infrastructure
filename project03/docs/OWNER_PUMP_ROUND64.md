# 第六十四轮：有预算的核心拥有者调度入口

日期：2026-11-10。

LocalAdapterSession 新增非阻塞 pump(at, outcome_budget)，默认每轮八个结果信封，允许范围 1..64。无效预算在调用核心或取走结果前拒绝。这里的预算是结果信封数；当前一个信封最多包含两条普通限价模拟回报，重复报告也占预算，不将循环次数伪称为性能实测。

每轮先 sync_faults，故障记录提交失败则立即返回，不取走业务报告。若已有待重试证据，返回 Blocked，保持显式 retry_reports 边界。正常处理至多预算个结果，遇到非 None/Duplicate 立即停止；结束前再次采样归并故障，使本轮报告提交失败产生的 EvidenceFailure 有机会在同一轮留下核心记录。故障或报告的失败仍保持门闩关闭，重复摘要不增加核心调用。

返回 LocalPumpResult：错误、已取出的结果数、成功故障更新次数、保留报告数和当前预算耗尽提示。保留失败的信封也计入已取出数，不代表提交成功；budget_exhausted 只描述本次观察时还有队列结果，不能证明之后不会再有生产者消息。

故障先归并、报告有限消费，使外层拥有者能在两轮之间安排 Kill、定时与其他控制；pump 不等待新报告、不等待工作线程退出，不以一次调用无限排空不断到来的消息。队列和门闩仍使用 mutex 短临界区；这里的非阻塞指不等新输入，不是无锁或 wait-free 保证。它不创建新的核心线程，也不接管调用方其他 CoreLoop 入口；完整四上下文 RuntimeRunner 仍需拥有整个生命周期并调度该入口。

新增四项回归：预算一轮只消费一个结果、下一轮继续且空轮不调用核心；已有丢失故障提交失败时报告仍留在队列，重试先归并再处理；报告失败停止本轮并记录故障，后项不得越过，显式重试后查询对齐且不重开；无效预算与非拥有者线程不推进核心。

范围：只对现有适配器结果和故障摘要提供拥有者调度入口，不宣称已经完成行情/控制/定时/Writer 四通道公平调度、实时期限或生产吞吐。没有真实日志资格、恢复复位、真实 SDK 或 TSan 结论，M1C 尚未整体完成。

最终验证：2026-11-10-owner-pump-debug / release 干净构建均通过 326 项测试、28,783 次断言，零失败。新增四项调度回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过；十四份既有功能输出在 Debug / Release 间、与第六十三轮之间均逐字节一致。未验证 Linux、TSan 或长稳。
