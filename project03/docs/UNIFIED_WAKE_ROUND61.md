# 第六十一轮：适配器统一唤醒

日期：2026-11-10。

新增单消费者 WorkSignal：mutex/condition_variable 保护 pending 与 closed。通知先于 wait 到来时保留 pending，多次通知可合并；谓词等待处理虚假唤醒。close 永久关闭并唤醒消费者，不支持重开。它只是工作提示，不能作为队列长度、消息已处理或业务恢复的证明。

LocalAdapterSession 新单与撤单成功入各自队列后通知同一个信号；finish/析构先关闭两条命令通道再关闭信号。适配器每轮仍最多处理四条撤单，再检查一条普通命令；只有本轮没有处理控制且普通队列为空时才等待信号。取消十毫秒定时轮询；有新任务或关闭才唤醒，保留先前任务在 close 后排空的语义。

不会丢失“空队列检查与 wait 之间”的通知：生产者入队后写 pending，消费者进入 wait 时在同一信号锁下读取它；若消费者已处理消息但通知稍后才到，只会多做一次空队列检查，不会捏造任务。队列仍是任务事实来源；关闭信号也不让消费者跳过尚未处理的队列项。

新增五项回归：通知先于 wait 被保留且合并；真实线程等待后通知唤醒；关闭唤醒且不可重开；空闲适配器被新单和撤单唤醒并查询对齐；finish 唤醒空闲适配器并 join。既有排队后 finish、Kill、容量、溢出与重试测试继续覆盖关闭排空和风险保留。测试不通过 sleep 制造交错，也不按毫秒阈值宣称性能。

范围：这里只统一适配器两类命令的唤醒，尚非核心、Writer、BridgeIO 四上下文的完整调度器。核心统一故障事件、心跳、真实日志资格、恢复与成交回报并发矩阵仍待实现，M1C 尚未完成。WorkSignal 拥有者必须在析构前关闭并 join 等待线程；不支持多个消费者共享 waiting 观察值。

最终验证：2026-11-10-unified-wake-debug / release 干净构建均通过 312 项测试、28,611 次断言，零失败。新增五项唤醒回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过，十四份功能输出在 Debug / Release 间、与第六十轮之间均逐字节一致。未验证 Linux、TSan 或长稳，不据此宣称延迟降低多少。
