# 第六十五轮：运行器拥有核心与适配器生命周期

日期：2026-11-10。

新增 LocalRuntimeRunner，按声明顺序先创建 CoreLoop，再创建 LocalAdapterSession；析构时先销毁会话、关门和 join，再销毁核心。核心与会话均为私有对象，公开 API 只返回 const CoreLoop 及只读轨迹；正常 API 无法绕过会话直接修改核心或只改核心 Kill 而漏关适配器门闩。观察引用仍只允许在拥有者线程使用，不是跨线程快照。

统一 step 接受显式启动、参考价、新单、受限撤单、成交刺激、Kill、预算报告处理、显式重试、finish。每次拥有者调用记录输入、返回码、可用的核心结果/泵结果、核心 canonical 摘要和门闩观察值。轨迹仅为内存中的已接纳指令记录；未接纳输入不新增帧，适配器跨线程自然顺序和完整内部核心调用日志尚未统一采集，不能宣称耐久审计或完整重放。

普通指令额度默认 128，另保留 16 条收尾额度；可配置上限分别为 1024/128。耗尽普通额度后关闭新增发送资格，仅允许 Kill、受限撤单、pump、retry、finish 使用收尾额度。收尾也有限，耗尽明确返回 Capacity；析构仍关门并 join，不会通过重置计数或门闩伪造恢复。输入字符串上限在记录前检查，轨迹向量预先保留固定槽位。

finish 停止接收新实验任务并 join，但仍允许后续 pump/retry 处理已有报告。它不自动撤销活动订单，不将核心预占或外部风险清零；核心模式可能仍为 Ready，而运行器与发送门闩已经关闭，这两种状态不能混为交易许可。显式 Kill 仍单独记录。异常后运行器关门并停止接受后续输入，不重新启动发送。

新增四项组合回归：启动→新单→报告→部分成交→Kill→撤单→finish→报告及独立查询对齐；普通额度耗尽仍可 Kill/finish/pump、未调用订单保留风险、收尾额度也可耗尽；工作线程完成后仍能排空报告且不能新发单；只读核心接口、拥有者线程、时间倒退与超长输入在适当边界拒绝。

范围：两个执行上下文（拥有者调用方、适配器线程），不是完整四上下文 RuntimeRunner。当前接入显式执行指令；原 LocalQuoteRunner 的 MarketState/策略链路尚未迁移到此类，不是自动报价运行时。没有 Writer/BridgeIO、真实 SDK、耐久发送资格、心跳全调度或恢复复位；仍需这些阶段条目与更多并发故障证据，M1C 尚未整体完成。

最终验证：2026-11-10-owned-runtime-debug / release 干净构建均通过 330 项测试、28,855 次断言，零失败。新增四项生命周期组合回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过；十四份既有功能输出在 Debug / Release 间、与第六十四轮之间均逐字节一致。未验证 Linux、TSan 或长稳。
