# 第六十六轮：行情与策略进入拥有型异步运行器

日期：2026-11-10。

LocalRuntimeRunner 增加显式可选 RuntimeQuoteConfig。它绑定 MarketState 与策略的完整业务范围、合约规则、来源、epoch 和年龄配置；不匹配拒绝构造。报价模式禁止原始 SubmitOrder/ReferenceMark 输入绕过资格检查；原显式执行模式保留。

新增完整行情快照、断线、订阅切换和带交易时段的定时输入。合格快照生成策略目标，参考价和规划结果经私有核心及会话进入适配器线程。断线/过期触发对已确认活动订单的受限撤单；Created 阶段不能假定已发送或可直接释放。后续 pump 收到接受证据后会继续规划或撤回。

每次只执行一个计划。价格变化时先请求撤旧，不做同步第二轮建单；取消终态未进入核心前，旧槽位仍占用。pump 有预算时若仍有结果待处理，暂不建立替代单。之后处理完回报，再从核心当前状态重新规划，实际通过异步终态后才能补单。

增加 QuoteStrategy::refresh：从当前 MarketState 合格快照重新计算库存目标，不冒充收到新的行情，也不修改其 received_at。原 evaluate 的重复序号规则保留；refresh 依赖 MarketState 的来源、代次、高水位及年龄资格，目标 generation 由运行器单调生成。这样成交后即使没有新盘口，也能重新计算单侧库存剩余量，避免沿用成交前的旧目标。

RuntimeFrame 增加行情健康、策略决定及本次计划，便于查看为何等待、撤单或补单。它仍不是完整内部核心事件日志或耐久重放材料。定时输入须显式提供交易时段，不把逻辑时间自动换算为真实交易所时间；仍是固定本地 profile。

补齐异步门闩边界：报价模式初始没有行情资格；MarketState 失效后，在门闩同一把锁下撤销 market_ready 并推进 dispatchEpoch。尚未承诺的旧排队/领取许可因此被阻断，重新取得合格行情也不能复活旧代次。已 CallCommitted 的调用仍保留原来边界，不能保证其不会随后进入对端。行情恢复只恢复该独立资格，不解除 Kill、回报丢失或其他永久关闭原因；open 和 market_ready 不能任取一个当作完整发送许可。

六项新增回归覆盖：重定价须等待两侧取消终态，预算只处理一侧时不补单；断线必须新订阅加新鲜快照才恢复；定时检查原快照过期并撤单、原始参考价不能绕过报价模式；同一快照下成交达到库存限额后抑制买侧，撤掉旧卖开仓，再建立卖平今并查询对齐；门闩行情资格恢复不复活旧许可、Kill 不被行情恢复解除；工作线程启动前断线时，已排队新单不进入对端且核心保留预占。

前一版组合构建通过后进一步审查发现排队许可也须受行情资格约束，因此补齐同锁 qualification 与两项回归，再使用 final 新目录构建。前一版不作为最终交付证据。

边界：当前行情及策略在两个执行上下文的拥有型运行器中通过局部组合测试，不代表全部 M1B 场景已逐一迁移或完整故障调度已完成。行情年龄仍在拥有者处理输入时检查，不是独立看门狗；核心心跳门禁仍待接入。失败报告保留时仍需显式重试；旧许可未调用也不自动释放核心预占，其后查询/未发送证明仍需推进。故障、未知订单与关闭期间的控制策略继续按 M1C 剩余矩阵推进。Writer/BridgeIO、恢复复位、真实 SDK 与 TSan 仍未完成。

最终验证：2026-11-10-runtime-quote-final-debug / release 干净构建均通过 336 项测试、28,952 次断言，零失败。新增六项回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过，十四份既有功能输出在 Debug / Release 间、与第六十五轮之间均逐字节一致。未验证 Linux、TSan 或长稳。
