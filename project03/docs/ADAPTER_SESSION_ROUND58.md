# 第五十八轮：核心接纳到适配器线程的本地交接

日期：2026-11-10。新增 LocalAdapterSession，使用核心调用方与适配器工作线程两个执行上下文；不是完整四上下文 RuntimeRunner。

submit 只能在创建会话的核心线程调用。它先执行 core.step；只有本次成功应用且分配了订单，才读取核心真实分配的 command、order、reservation、业务范围和策略身份，派生本地内存交接记录。重复 client 请求、风控或格式拒绝不进入发送队列。原有 CoreLoop 的事务与风险逻辑没有改写，也没有把其 M1A 接口冒称为完整生产授权效果。

命令复制为自有值，经有界 FIFO 投递。工作线程内部构造、使用、查询并销毁 LocalSimVenue；不访问 CoreLoop、Order 或 Position 的引用。它经过 claim / TryCommitCall 后调用对端，将许可返回状态和对端报告作为自有结果投递。核心线程取回报告后负责调用 core.step，处理失败仍必须保留证据，不得假定 receive 就等于提交成功。本轮会话未封装失败报告的自动重试。

命令入队失败同步关闭门闩并撤回本次未调用许可，核心预占保持。关键结果收件箱满时先同步关闭门闩，再处理下一条命令；队列排空不解锁。报告丢失不会替核心捏造 NotSent 或取消终态。kill 先同锁关门，再由核心线程提交 KillRequested。必须经会话 kill，不能只调用核心 KillRequested 就假设适配器门闩也被关闭。

start 显式启动适配器线程，也允许先排入有限命令以测试预定交错。finish 关闭命令输入、排空、join，返回工作线程生成的独立查询快照，并停止新的会话提交。它不撤销对端仍活动的订单，也不将核心改为零风险；关闭线程和关闭外部订单是两回事。析构只关门、关闭通道和等待线程，不写核心或释放预占。

本地授权到期单位在此组件中明确为毫秒：创建时的逻辑时间加上 steady_clock 测得的排队年龄用于领取和承诺检查；不把它冒充核心心跳或交易所时间。会话绑定固定配置，要求从无订单的 Ready 核心与匹配初始模型启动，每个核心只应交给一个会话驱动；尚未引入独占租约来阻止调用方同时创建多个会话，故此 API 仍是受控本地实验接口。

测试覆盖：正常核心接纳→适配器实际接收→报告入核心→独立查询对齐；启动前 Kill 不调用且预占保留；命令队列满；回报溢出阻止后续领取并保留风险；重复请求/核心拒绝不发送；外来线程写核心入口及配置不匹配被拒绝。

限制：内存前缀固定标记不是 fsync 或真实 Writer 确认；没有新增 Writer/BridgeIO、完整调度公平性、撤单命令、成交命令、恢复复位、真实 SDK 或生产发送能力。报告溢出尚未作为核心统一故障事件归并，现由共享 gate 保持停领。不要把局部双上下文闭环记作完整 M1C。

最终验证：2026-11-10-adapter-session-debug / release 干净构建均通过 298 项测试、28,510 次断言，零失败。新增六项适配器交接测试分别经 CTest 和聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过；十四份既有功能输出在 Debug / Release 间、与第五十七轮之间均逐字节一致。未宣称 Linux、TSan 或长稳验证。
