# 第二十二轮：报价运行器独立导出与工作台入口

日期：2026-11-07。

## 新增产物

`p03_export_quote_runner` 运行固定五步接口实验，输出 `p03.quote-runner.v1` JSON。五步依次为：初始双侧报价；更新盘口并先撤后建；新买单成交一手；异常盘口撤回剩余报价；Kill 核心。导出前从相同初始配置重跑原始内存输入，检查结果与最终核心状态一致。

JSON 每帧包含运行器 ordinal、逻辑时间、输入字段摘要、策略决定摘要、核心及对端四桶持仓、对端版本、核心订单价量与 B/H/P/L/V、实际核心调用类型和结果、输入/业务序号，以及核心状态摘要。为支持导出，运行器每个完成帧新增核心订单、持仓和模式的只读副本。

这是离线诊断投影，不是完整事件编码或可从 JSON 恢复运行的文件格式。内存原始输入重放由 C++ 测试和导出程序执行；没有 JSON 导入器、检查点恢复或持久化保证。

盘口标记为 InterfaceFixture，对端标记为 LocalSimulator，历史轨迹标记为 false。固定价格及成交指令是接口实验，不替换原标准 A.1.a 正常案例，不伪装公开市场数据。

## 页面

`demos/round02/runner.html` 从执行工作台导航进入。可以点击五步检查点或前后切换，查看核心调用表、核心订单表、两侧今多、订单未释放占用，以及输入/策略观察值和核心摘要。

最后 Kill 时，订单占用为零，但已成交今多仍为一手。页面明确区分停止报价和清仓，不能用 Kill 成功暗示持仓已归零。

页面只加载已生成 JS 文件，不运行 C++，不发送交易操作，无服务器依赖。`prepare-quote-runner.cjs` 先验证完成构建的当前源码/归档源码/产物哈希，再检查撤单终态先于替代新单、异常盘口撤回、最终数量守恒和持仓，才生成页面数据。来源显示构建配置、run、导出程序名及原 JSON SHA256。
