# 第五十六轮：M1C 有界队列基础

日期：2026-11-10。按 ADR003 使用 mutex / condition_variable，不引入无锁队列。

新增 BoundedQueue<T>：构造时分配固定槽位，容量范围 1..65536；FIFO、环形复用，队列自身操作不扩容。消息要求 noexcept 移动构造与析构。消息自身可能拥有的堆内存仍须由各通道 profile 另行约束，固定槽位不等于完整内存预算。

try_push / try_pop 明确区分 Full、Empty、Closed；push_until / pop_until 使用 steady_clock 绝对截止时间。失败的 push 不移动调用方消息。谓词等待处理虚假唤醒；关闭幂等，唤醒所有等待者。关闭后拒绝生产者，消费者继续按 FIFO 排空已经接受的消息，之后返回 Closed。close 是通道生命周期操作，不提供重新开启。

snapshot 在同一互斥锁下取得容量、深度、高水位及等待者数量。这些是观察值，不能拿一次 snapshot 当作下一次入队必定成功的承诺。队列拥有者必须在析构前 close 并 join 使用它的线程；不能一边析构一边等待。关闭不等于订单取消或外部网关静止。

七项测试验证容量、环形 FIFO、move-only 所有权、立即超时、关闭后排空、关闭唤醒全部生产/消费等待者、容量释放与新数据唤醒，以及真实线程传递两千条消息后关闭排空。另有双生产者并发场景验证每个生产者的顺序、无重复丢失及深度不超容量。测试线程不直接调用测试断言计数器，结果返回测试主线程核验；测试等待有截止时间，无任意 sleep。

边界：这是 M1C 队列组件，不是四上下文 RuntimeRunner。尚未实现通道优先级/公平预算、关键回报溢出的同步 gate、lossGeneration、核心心跳过期、安全 claim/调用承诺/静止边界。行情、成交、授权命令、日志、观测不能不加区分地共用一个满队列策略；后续按正式架构逐通道接入。现有 LocalQuoteRunner 仍是同步纯内存驱动。

最终验证：2026-11-10-bounded-queue-final-debug / release 均通过 285 项测试、28,358 次断言，零失败；七项队列测试分别经 CTest 与聚合执行验证。证据报告和离线包检查通过，Release 当前源码与 40 份产物哈希核验通过。十四份功能输出在 Debug / Release 间、与第五十五轮之间均逐字节一致。仅在本机 Windows / MSVC 验证，未宣称 Linux、ThreadSanitizer 或长稳压力验证。

首次 Debug / Release 构建因超时测试误对 QueueResult 使用 `.result` 而编译失败；修正测试后使用 final 新运行目录重新构建，保留原失败日志，不把失败构建计入通过证据。
