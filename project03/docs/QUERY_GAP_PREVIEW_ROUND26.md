# 第二十六轮：运行器查询缺口场景导出与可视核对

日期：2026-11-07。

## 独立 C++ 场景

新增 `p03_export_quote_runner --query-gap`，运行八个明确的接口实验输入：初始报价、对端买单成交且暂扣推送、收到盘口但禁补单并撤存量、故意缺成交行的查询、完整查询补齐、迟到推送、合格新盘口重新规划、最后 Kill。

暂扣后，对端今多为 1，核心为 0，pending_reports 为 1。缺行查询返回 Blocked，零核心调用、核心状态摘要不变，pending 继续为 1。完整查询后两侧今多均为 1，pending 归零；原推送迟到时核心返回 Duplicate。最后撤单占用归零，但成交持仓保留为 1。

新鲜盘口重新规划卖侧时优先平已确认今多；本场景只撤销该平仓报价，没有执行平仓成交。新鲜盘口可重新规划不代表签发完整恢复证明或复位真实发送 gate。

导出前执行同配置内存原始输入重放。新增 C++ 用例逐帧核对返回值、核心摘要、待补齐数、对端持仓与核心调用数，不只比较最终结果。

## 页面

报价轨迹页新增“暂扣回报 / 查询补齐 / 去重”选择，共八个检查点；原五步报价和六步到期场景保留。新增已知待补齐回报读数，与核心/对端今多及未释放订单数量并列。

切换检查点时，同步显示输入、策略决定、调用序号、订单快照和场景说明。切换场景时回到首帧并更换原 JSON SHA256，避免用另一场景的来源标记解释当前轨迹。

## 数据与验证

构建脚本封存 quote-query-gap.json，带新增标记的运行必须包含该文件，产物总计 28 项。生成脚本先验证完成构建、当前/归档源码及产物哈希，再检查分歧、禁补单、缺行查询零调用/状态不变、完整补齐、推送去重、最终数量守恒及持仓。

Node DOM 检查覆盖八帧选择、两侧分歧、pending、缺行查询空调用、完整补齐、迟到去重、最终未清仓状态、来源哈希，以及切回原报价场景。旧工作台和其他轨迹逻辑检查继续运行。

证据目录为 `evidence-local/2026-11-07-query-gap-preview-debug`、`evidence-local/2026-11-07-query-gap-preview-release`。
