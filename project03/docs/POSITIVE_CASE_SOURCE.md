# 正向演示案例选型：官方订单生命周期

核对日期：2026-11-05。状态：已接入 C++，并作为工作台默认正向案例。结果见 STANDARD_NORMAL_ROUND05.md。

## 案例来源

FIX Trading Community 官方《Order State Changes》，July 2020，A.1.a（Filled order）的正常成交分支。

官方文件：https://www.fixtrading.org/wp-content/uploads/download-manager-files/Order-State-Changes.pdf

该案例给出一笔数量 10000 的订单，经接收确认后分三笔成交：2000、1000、7000；最终累计成交 10000、剩余数量 0。采用正常接受分支，不采用表中的拒绝分支。

## 用于本项目的边界

这是公开的标准规范案例，不是某笔真实客户订单的历史流水。可以成为有出处的 OMS 正向基准，不能宣称复刻真实交易或已实现 FIX 接口。

项目主线仍为 SHFE/RB/CTP。FIX 示例只提供正常订单生命周期的参考，不证明 CTP 字段、回报顺序、开平、持仓或资金语义。

原例的数量必须作为来源值保留。若适配为 RB 手数，需要明确标记缩放规则，区分源案例数据与本地派生输入；不能把 10000 直接说成真实 RB 委托手数。价格、合约、账户、开平与费用若无来源，不标记为实盘数据。

## 已实现演示结构

正常路径采用来源明确的确认、分笔成交、全部成交基准；独立保留目前的撤单竞态与重复成交回归。故障实验应从正常基准上注入丢失、重复、乱序等变化，记录原始场景、注入规则与实际结果。
