# 第六十轮：停领新单后的受限撤单通道

日期：2026-11-10。

LocalAdapterSession 新增独立撤单 FIFO，默认八个槽位，不占新单队列容量。会话撤单请求总预算默认六十四次、上限五百一十二次；这是有限实验预算，不是按秒节流器。满队列或预算耗尽在核心创建 cancel action 之前拒绝；同一核心拥有者是唯一控制生产者，消费线程只能释放容量。

cancel 允许新单门闩关闭时执行，但仅处理已收到接受证据的现有订单；Created 阶段先返回 Blocked，不让优先撤单越过仍未确定发送的新单。核心 RequestCancel 成功后，将核心实际分配的 cancel action 与 order 身份复制到控制队列。完成会话后拒绝新增撤单；会话 Kill 保持，不因撤单成功而复位。

适配器仍独占 LocalSimVenue。每轮最多处理四个撤单，再检查一个普通命令，避免控制持续到来时永久饿死普通通道；空闲时等待普通命令最多十毫秒，再检查控制通道。这个轮询等待上限不是实际延迟保证，也不是最终运行时的统一唤醒调度器。finish 和析构同时关闭两条命令通道，finish 排空已接受任务后 join。

撤单结果进入已有关键结果收件箱，包含 cancel action 标识；确认与精确取消终态沿 process_reports/retry_reports 处理。提交请求不释放订单占用，只有相应证据成功入核心才改变风险分区。报告失败仍保留原始结果和位置，成功重试不重开新单门闩。控制与新单共用同一适配器线程，不承诺外部调用阻塞时可即时撤单。

新增四项回归：Kill 后新单拒绝而撤单到达对端，终态后零占用且查询对齐；撤单确认提交失败时保留确认和终态两条报告，显式重试后对齐；预算拒绝不把第二订单标为 Requested 并保留其风险；未确认新单不能被撤单越过、未知订单和会话完成后请求被拒绝。

边界：没有增加成交命令、核心统一故障事件、恢复复位、Writer/BridgeIO、真实 SDK 或完整调度器。保守拒绝 Created 订单的撤单不等于已解决未知发送状态，仍需查询与后续对账。M1C 尚未整体完成。

最终验证：2026-11-10-adapter-cancel-debug / release 干净构建均通过 307 项测试、28,583 次断言，零失败。新增四项撤单回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过；十四份功能输出在 Debug / Release 间、与第五十九轮之间均逐字节一致。未验证 Linux、TSan 或长稳。
