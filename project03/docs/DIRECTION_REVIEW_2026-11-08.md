# 项目完成方向核对

日期：2026-11-08。依据用户目标、V1.1 正式架构 §3、§5、§10、§17，以及当前工作副本源码。交接文件用于核对目标与技术约束，其历史“等待批准”要求已被用户后续自主推进授权更新。本次不修改原始交接件。

## 结论

**产品与技术方向基本正确，阶段推进方式需要收拢。** 当前 C++ OMS、四桶、风险预占、独立模拟、异常证据和重放直接服务买方执行基础设施；没有把项目做成收益回测或另一个交易所撮合引擎。

但近期较多增量集中在局部异常、离线展示、证据包装和微基准，正式阶段主线没有同步收口。不能用轮次、测试数或页面场景数量代表完成度。下一批应以 A02/A03 与 M1B 收口为目标，随后进入 M1C 真实运行时，不再把新展示和微优化作为默认主线。

## 1. 保持的正确方向

| 目标 | 当前吻合之处 | 边界 |
|---|---|---|
| C++ 量化开发工程师能力 | C++20 状态机、内存事务、强类型身份、账本与风险、回归和诊断 | 尚无真实并发、网络和耐久运行证据 |
| 买方交易执行 | 策略意图、先撤后建、开平路由、OMS、预占、回报处理 | 简化策略仅驱动负载，不以收益为目标 |
| 正确性和可靠性 | 迟到/重复/矛盾成交保留，失败重试，Kill 后继续入账 | 同步本地正确不等于实际发送 gate 或断线恢复 |
| 专业工作台 | 展示 C++ 输出、证据缺项、风险占用和输入尝试 | 离线观察不是在线控制，浏览器不拥有交易状态 |
| 单合约先行、为扩展打基础 | InstrumentKey、BusinessScope、策略限定身份和模块边界 | 当前仍 SHFE/RB 单实例，账户组合资金和多合约调度未实现 |

独立 LocalSimulator 不是重复项目一的交易所撮合引擎；项目二的网络能力也不能在未核对源码和边界前被视为本项目已经拥有的运行时。

## 2. 需要纠正的阶段判断

V1.1 §17.2 明确：**M1A 与 M1B 可以先用纯内存材料验收。**

- M1B 核对 A02 行情、A03 策略与规划、完整报价轨迹和独立本地查询证据。
- 真实有界队列、四线程职责、发送 gate 和并发交错属于 M1C。
- 实际 JournalWriter、落盘确认和持久化发送保证属于 M1D。
- 独立 WebBridge 与在线控制属于 M1E。

因此，“没有线程/耐久日志/在线桥接”是整体未完成的真实缺口，**不是这些模块必须先完成才能验收 M1B 的理由**。上一份总结对 M1B 的后续建议不够精确，现按正式门禁修正。

本次也不直接宣布 M1B 完成：当前 MarketTop 只有顶档值、静态来源/epoch 和策略侧检查，未发现正式 FeedNormalizer / MarketState / FeedHealth 实现。V1.1 §10.1 要求 validDepth、有效字段、订阅 generation、接收年龄以及 AwaitingData / Valid / Stale / Invalid / Recovering 资格；A02 还要求重连旧快照不得误置 Valid。这是应具体核对和补齐的主线缺口。

## 3. 按优先级列出的发现

### 高优先级：补齐行情业务层并收口 M1B

现有源码入口：[MarketTop 与策略](../include/p03/quote_strategy.hpp)、[策略检查](../src/quote_strategy.cpp)、[同步运行器](../include/p03/local_quote_runner.hpp)。当前数据可以驱动闭环，但不能用一个 healthy 布尔值和固定 epoch 代替完整行情资格管理。

下一交付应包括明确的本地行情 profile、有限档位/有效字段表示、行情状态及失效原因、重订阅/重连代次隔离，并接入现有策略与运行器。档位只采用实际提供的数据，不补造 MBO、交易所连续序号、逐笔或排队位置。

以 A02/A03 建证据映射，覆盖缺档、无效价格数量、时效边界、旧代次快照、重新建立有效行情、撤旧等待、自交叉及库存限制。只有剩余缺项关闭，才形成 M1B 收口记录；不额外把后续阶段功能塞入该门槛。

### 高优先级：从同步实验进入真实受控运行时

当前 LocalQuoteRunner 明确没有线程、后台时钟或 SDK。这是测试执行器，不能在介绍中当作 RuntimeRunner。

M1C 按已批准 ADR003 使用有界 mutex/condition_variable 队列，不默认改成 SPSC 或无锁。实现 CoreLoop 单写者、AdapterExecutor 所有权、队列关闭唤醒、通道优先级/公平、超时与暂停，以及真实 gate 的 claim/调用承诺/静止边界。回报溢出须同步关闭新增发送资格，不能只给页面设置标志。

### 高优先级：按顺序实现耐久性与发送约束

事实类型和离线 JSON 归档不等于交易 Journal。M1D 必须落实连续日志前缀、同步确认、半写/损坏处理、未确认意图不发送、未知发送不盲目重发，以及禁外发的回放执行器。文件 Writer、发送 gate 与恢复资格需要实际失败测试，不能用更多内存重放替代。

### 中优先级：真实市场与扩展路线保持明确

当前 rb_FIXTURE、显式日历和模型资金适合作为测试材料，但不代表运行日真实合约目录、临时参数或当前 SDK 语义已核验。保留合约/profile 的版本与来源基础；真实协议和环境验证按 M2 推进，不因本地测试通过就开放真实发送。

近期继续单合约完成闭环。多合约按账户级共享资金、合约级订单持仓、策略级限额分层演进；不能只复制几个 CoreLoop 或页面就声称账户风险已共享。多品种进一步需要放开有证据支持的市场规则，而不是只改合约字符串。

### 中优先级：展示、事故和教学回到服务主线的位置

现有八种场景可以展示机制，但不等于四个历史事故实验已完成。后续按既定范围保留事实来源、构造假设、保护对照和实测结果，不能把合成输入说成真实历史轨迹。

新 UI、微基准、性能优化和归档功能优先用于关闭阶段验收问题；暂不继续独立扩大这些分支。性能诊断成果保留，不以它们代表 M3 完成，真实排队、持久化等待、open-loop、长稳和 Linux 证据仍欠缺。

T5“用户能调试、能解释”也需要交付：每个主线模块附调用路径、复现命令、失败案例和调试说明。代码存在和测试通过不能证明用户已理解；教学不应变成重复审批或阻塞开发的考试。

## 4. 下一批工作的完成标准

1. 建立 A02/A03 收口矩阵，逐项列出当前源码、测试证据和具体缺项，不以阶段名称笼统等待。
2. 补齐并接入本地 MarketSnapshot / MarketState / FeedHealth，完成行情资格与旧代次隔离的闭环回归；明确真实 profile 尚未接入。
3. 复核 M1B 报价/撤成/独立查询证据，满足后正式收口；接着按 ADR003 开展 M1C，不额外等待例行人工批准。
4. M1C 后推进 M1D、M1E、M1F；M2 真实协议、M3 性能、M4 四案例与恢复矩阵、M5 七页工作台/CI/复现/长稳按原路线逐项验收。

## 5. 检查范围

本次为方向和门禁核对，没有改变业务代码或重新运行全部测试。读取正式架构与当前关键源码，并重新通过最新 Release 的源码、39 项构建产物和离线包验证。业务测试依据仍为最新 Debug / Release 各 261 项、28,093 次断言；该数字不作为完成度比例。
