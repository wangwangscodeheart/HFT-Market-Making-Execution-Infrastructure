# 第四十五轮：不同状态规模下的参考价更新耗时

日期：2026-11-07。

新增 p03_core_state_benchmark，受控构造两类状态：保留未成交订单（working），或保留已成交订单与成交记录（filled）。每类分别取 0、8、32、63 笔，共八档。每档状态建立后，预热 20 次 ReferenceMark，测量 100 次，共 800 个样本。订单容量仍为 64，本轮不修改风险或容量机制以迁就诊断。

每笔委托一手，filled 档逐笔成交一手；两类订单和成交身份显式唯一。建立状态不计时。计时只包围 core.step，保留当前内部复制、校验、分配和资源重算；额外检查不计时。每次更新后校验订单/成交记录数、四桶持仓、资金需求和核心不变量；结束核对工作单占用与成交后持仓。它是确定性的工程负载，不是官方正常成交案例的历史扩展，也不是随机市场数据。

所有样本和 min/p50/p99/max 封存为 core-state-benchmark.json。Node 独立重算分位数，检查档位集合及持仓/占用对应关系；新增三项负控拒绝错误占用、档位缺失和错误分位数。上一轮 3,000 次标准案例诊断及四项负控继续执行。

只测 ReferenceMark，用于暴露状态规模带来的复制、校验等整体处理成本；不能由此单独分解每种操作的成本，不能外推新报单、撤单、长期持续负载或网关性能。不绑核、不隔离主机负载、不承诺跨次计时单调增长；Debug/Release 分别记录。

本次结果显示状态规模相关成本明显，单订单基线不适用于更大状态。两种零状态结构相同但计时不同，体现测量噪声和运行顺序影响；这里不据八档数据宣称严格复杂度，也不将全部耗时归因于某一个函数。

Debug / Release 各 246 项业务测试、27,574 次断言，0 失败、0 跳过。每配置独立完成原有 3,000 次和新增 800 次测量；原有四项加新增三项诊断负控通过。十二项证据负控、四项包负控及工作台/回放/八种报价场景逻辑检查通过。十三份确定性诊断输出及静态界面清单一致，计时分布不要求相同。
