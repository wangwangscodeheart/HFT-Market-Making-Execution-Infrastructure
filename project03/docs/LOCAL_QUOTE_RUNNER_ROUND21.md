# 第二十一轮：有序输入的本地报价驱动

日期：2026-11-07。

## 实际实现

新增 LocalQuoteRunner，独占一个核心、独立对端和策略实例。外部输入限定为完整最优档快照、明确的模拟成交指令和停止报价指令。step 是同步调用，没有线程、系统时钟、SDK 或外部发送资格。

每份被接受的输入得到运行器 ordinal，记录原始输入和逻辑时间、策略决定、实际核心输入及 StepResult、核心状态摘要、独立对端查询快照。ordinal 与 core_sequence 分开：一次外部输入可能产生多个核心事件。核心只由该驱动写入；公开访问接口为 const。

合格盘口先生成目标，再以显式 ReferenceMark 事件更新核心参考价，随后执行规划。价格变化时先撤旧、消费对端真实返回的撤单及终态证据，再在第二次规划中建立新报价，不凭撤单请求假设已撤。每个新单先经核心风控，再向对端传递明确消息。对端业务拒单若带终态仍交给核心释放资源。

异常盘口触发报价目标撤回，运行器尝试撤现存报价；停止输入先 Kill 核心，再请求撤存量单。停止标志和订单终结不是一回事，撤单失败会保留原风险。运行器不支持撤回已经发生的成交。

## 顺序、容量与失败

逻辑时间倒退时不进入核心、不生成新轨迹。输入数和核心调用数均有上限；每次接受输入前保留保守调用预算。容量不足会锁住运行器，禁止后续进入核心；它不伪造已撤单或释放已存在的对端订单。此时仍可能有存量风险，不能把 stopped 当成清仓或已完成关闭。

一份市场输入中的多个核心调用不是整体事务。例如买单已经被接纳后卖单被资金检查拒绝，买单及预占保留，轨迹保留每个实际结果；该情况已加入测试，并验证后续停止指令能撤掉存量。异常会使运行器停住并向调用方传播，不宣称拥有跨组件回滚。轨迹 completed 只在状态/对端观察和不变量检查完成后置真；业务拒绝也可以是完整记录，completed 不代表业务成功。

## 验证方向

新增九项测试覆盖初始两侧报价、盘口更新的先撤后建、异常盘口撤回与 kill、成交和重复成交、原始输入重放、时间倒退/容量、对端独立资金拒单、部分计划风险拒绝以及非法基线/核心调用预算。重复运行比较核心摘要、对端版本/持仓、核心调用数量、序号和结果。

构建目录为 `evidence-local/2026-11-07-local-runner-debug` 与 `evidence-local/2026-11-07-local-runner-release`。输入价量为明确标记的接口测试夹具，不是新增随机行情、公开市场数据或历史事故轨迹。

上述是中间构建，最终含完成标记与两项边界回归的目录为 `evidence-local/2026-11-07-local-runner-sealed-debug`、`evidence-local/2026-11-07-local-runner-sealed-release`；当前源码以最终目录为准。

## 边界

最终 MSVC Debug / Release 各 185 项测试、26420 次断言通过，零失败/跳过；源码、注册表、聚合结果和 CTest JUnit 一致，八项证据负控及工作台新旧 Node 逻辑检查通过。两种配置的既有正常/恢复导出轨迹相同；运行器输入重放一致性由新增 C++ 用例验证。运行器轨迹尚无独立 JSON 导出，不能把原有恢复 JSON 视为报价运行器证据。未验证原生浏览器布局或目标 Linux 平台。

目前可由调用方连续投递有序输入；这不等于后台持续报价服务。市场输入和策略状态仍未并入 CoreLoop 的统一 BusinessEvent 和持久化事件格式，运行器记录仅存在内存中。测试能从相同初始配置重跑，不支持中途进程恢复或独立存活柜台。
