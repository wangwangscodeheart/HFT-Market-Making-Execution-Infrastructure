# 第三十六轮：暂扣成交等待期间的精确重复抑制

日期：2026-11-07。

上一轮统一收件箱后，同一暂扣报告在提交失败期间反复释放，会重复占用队列。现在 LocalHeldReportInput 先查找完整相同的待交付报告；已在队列中时返回 Blocked，不调用核心、不重试、不追加，也不改变成交账本。显式重试成功后再次释放仍由核心返回 Duplicate。

精确匹配比较 Trade 全部内容、EvidenceStamp 全部内容与 Channel。它只用于本地暂扣释放入口，不对所有入队回报做全局去重；不同价格、来源、epoch 或通道不会被此检查合并。查询和推送间的经济成交身份去重仍由核心负责，证据冲突也不在收件箱隐藏。

新增连续十次释放失败暂扣报告仍保持队列长度一的回归，以及更改载荷、来源、epoch、通道时不视为精确重复的检查。队列仍为有限内存，真实不同报告超容量仍触发原有丢失锁定机制。

最终 Debug / Release 各 235 项测试、27,313 次断言，0 失败、0 跳过；四方测试清单、八项证据负控及 Node 页面逻辑检查通过。十二份诊断输出逐字节一致。最终证据为 evidence-local/2026-11-07-held-dedup-fixed-debug 与 evidence-local/2026-11-07-held-dedup-fixed-release，页面数据来自 Release。

首次测试把查询快照报告的通道误当成 Push，导致新增通道检查失败；已改成相对原始通道切换后重建。原 held-dedup-debug/release 失败记录保留，不作为通过证据。范围不包含真实网关、异步查询或耐久日志；未验证原生浏览器布局。
