# 第二十四轮：到期撤单实验导出与页面对照

日期：2026-11-07。

## C++ 场景

`p03_export_quote_runner --expiry` 新增六帧固定接口实验：逻辑时刻 1 接受盘口并报价；11 恰好达到 max_age=10；12 超过时效并撤单；13 重复检查；14 接受序号更新的新鲜盘口并重新报价；15 Kill 并撤存量。

边界帧不调用核心、不刷新参考价。过期帧实际产生六次核心调用：两笔撤单各经过请求、响应和终态。重复检查没有新核心调用。新鲜盘口后出现两笔新订单，旧单终态保留。此场景没有成交，全程核心和独立对端四桶持仓均为零。

导出程序从相同配置重放内存输入并比较最终状态；新增 C++ 测试还逐帧比较摘要、核心调用数和空操作边界，验证无调用帧没有改变核心摘要。未知导出参数返回 2。

## 工作台

报价运行器页面增加场景选择：原五步成交/Kill 场景和新六步到期场景。切换时回到首帧，表格、说明、核心调用、订单快照和原 JSON SHA256 一起更新。两种轨迹均从 C++ 执行输出生成；浏览器不计算订单结果。

新鲜盘口重新报价仅表示本地健康、来源、序号和时效检查通过，并再次经过核心风控；不是恢复证书、断线恢复或 gate 复位。调用者必须投递定时输入，没有后台计时器。

## 证据流程

构建脚本封存新增 quote-expiry.json，共 27 项产物。带 quote_expiry_export 标记的运行必须包含该文件；旧运行保持原范围。生成脚本先核验当前源码/归档和完成构建的产物哈希，再检查时效边界、调用顺序、占用释放及最终持仓，才生成两种页面数据。

Node DOM 检查覆盖六帧场景切换、边界空调用、过期六次调用、重复检查、新鲜盘口新占用、最终停止及来源哈希切换。原五步报价页、成交补齐页和原工作台回归同时保留。

证据目录：`evidence-local/2026-11-07-expiry-preview-debug`、`evidence-local/2026-11-07-expiry-preview-release`。
