# 第四十四轮：单线程核心事件耗时诊断

日期：2026-11-07。

新增 p03_core_step_benchmark，使用既有官方 FIX A.1.a accepted/filled 数量序列的本地缩放案例。每轮新建核心，执行 ReferenceMark、SubmitOrder、WorkingReport、三笔成交 2/1/7；50 轮预热不计入样本，500 轮测量共 3,000 次调用。每次调用后检查结果与不变量，每轮核对最终订单、持仓和完整核心摘要一致。

steady_clock 只包围 core.step；核心内部 copy/validate/swap、容器分配等当前实际工作包含在内，核心构造、输入准备、额外不变量检查、摘要生成、排序与 JSON 输出不包含。每类事件各保留 500 个纳秒原始样本，输出 min、nearest-rank p50/p99、max；另测 500 组相邻时钟调用，报告计时器开销分布，不作相减。clock period 是时钟类型刻度，不当作测量精度保证。

每轮只处理一个订单和三笔成交，核心不持续增长。这是小状态工作负载诊断，不是大订单簿、长期驻留容量、行情接入、SDK、网络、Journal、持久化或生产端到端性能测试。没有绑核、实时优先级、CPU 隔离或统计置信保证；机器其他进程和构建活动会造成噪声。Debug 与 Release 分开记录，不要求计时数据相同，不据此声明真实 HFT 吞吐。

构建封存新增可执行文件和 core-step-benchmark.json；报告独立校验所有原始样本、分位数与计时范围标志。四项负控验证错误分位数、样本缺失、负耗时和网关测量范围误标会失败。C++ 业务测试数与这些 Node 诊断检查分开统计。
