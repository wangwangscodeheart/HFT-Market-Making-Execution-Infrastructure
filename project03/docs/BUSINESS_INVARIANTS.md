# M1A 业务不变量与失败行为

这些规则由业务类实现，并由 `CoreLoop::invariant()` 和自动化测试交叉检查。以下“接单”“成交”“资金查询”均指人工提供的、明确标记的 fixture 证据，不表示已连接外部系统。

## 身份、会话和所有权

`OrderId/CommandId/CancelActionId/ReservationId` 是不同 C++ 类型，含显式实例与单调计数器。0 无效，耗尽必须拒绝继续生成。M1A 不持久化实例或计数器，不承诺跨进程唯一性。命令序号和 coreSeq 记录一次处理尝试；业务失败不创建半份订单。

只有 `CoreLoop::step(event, logicalTime)` 修改核心拥有的状态；调用者只能读取 const 视图。逻辑时间不得倒退；会话规则由版本化日历显式提供，夜盘民用日期不等于交易日。自然日午夜不搬桶、不清订单、不解除冻结。

## Q/B/R/E 与数量分区

- Q：原委托量；B：按经济成交键去重后记账的正常逐笔量；R：通过身份、来源、范围检查的累计成交下界。
- E：正常情形为 max(B,R)；H=E−B，表示已知发生但缺逐笔的成交；只改变 R 不会虚构成交明细或改四桶。
- P：未来仍可能成交；L：已被可靠精确终态证据证明不再成交而释放的数量；V：虽无未来执行，但最终成交量未知的部分。
- 始终有 B+H+P+L+V=Q，且五项非负，0≤B,R≤Q。冲突不能通过删掉有效成交来凑这个等式。

| 情形 | 分区 |
|---|---|
| 活动或未知 | H=max(B,R)−B，P=Q−max(B,R)，L=V=0 |
| 精确终态 F，且 F≥B、F≥R | R 至少提升到 F，H=F−B，L=Q−F，P=V=0 |
| 停止未来执行但无精确 F | H=max(B,R)−B，V=Q−max(B,R)，P=L=0 |
| 证据冲突 | L=V=0，恢复 P=Q−max(B,R)；已有 H 和 B 保留，停止新单 |

累计回报来源序号只在相同 source/epoch、且 fixture profile 声明可比时比较。较新序号给出较小数量、同版本异数量、较旧版本反而大于已见新版本，都属于矛盾；没有可比版本时只合并下界，不推导虚假的回调顺序保证。

## 终态、撤成和成交去重

终态不等于账本已结清。Q=3、先收到 T1=1、再收到撤单精确 F=2 时，分区是 `(B,H,P,L,V)=(1,1,0,1,0)`；T2=1 到达后为 `(2,0,0,1,0)`。只释放 1 手，T2 的查询/推送重复均不再改仓或扣费。

若可靠拒单/NotSent F=0 之后出现有效唯一成交，正常量在 Q 内必须记账，同时进入 Conflict、恢复保守占用。若恢复后的平仓冻结超过剩余仓位，保留真实负仓/冻结缺口并设置 `risk_deficit`，不截断成交、不把负数悄悄归零。接单证据与 NotSent/拒单互相矛盾时同样停止。

经济键包括账户、交易日、交易所、已声明的成交标识范围与 trade_id；不包括推送/查询通道、queryId 或回调时刻。同键同内容幂等；同键异内容保留原记录、隔离新内容并停止。不同 trade_id 即使价量相同也不能合并。

若某个有效唯一成交会使正常 B 超 Q，整笔成交进入 `LedgerDisposition::Exception` 的 X 记录，仍使用同一去重索引。X 参与保守暴露和资金需求，不挤进正常 B，也不拆一部分伪装成正常成交。

撤单动作有独立 ID 和有界历史。旧动作的重复回报不能覆盖最新动作。撤单请求不释放预占；动作回报本身也不是最终成交量证明，必须另有终止证据。Unknown 撤单结果会停止新意图，仍处理既有成交；之后补齐动作回报也不自动解除停止。M1A 不发送撤单。

## 四桶、基线和跨日

四桶顺序固定为 LongToday、LongYesterday、ShortToday、ShortYesterday。买开加 LongToday；卖开加 ShortToday；卖平今/昨分别减 LongToday/LongYesterday；买平今/昨分别减 ShortToday/ShortYesterday。不会用对向开仓隐式平仓，不实现 AutoClose。

平仓预占来自对应订单 H+P+V，按桶求和。唯一平仓成交同时消耗正常仓位和对应剩余预占，重复成交不再消耗。新意图建立订单、reservation、资金和冻结是一个候选状态事务；数量、资金、可平量、容量或预提交失败都不得留下半份状态。

PositionAnchor 是启动时的固定 fixture 基线：账户、合约、交易日、epoch 和覆盖说明固定，业务成交只改派生桶。当前只支持启动种子与其后增量，不支持装载含已应用当日逐笔的新基线；换锚/快照恢复均未实现。

外部持仓观察、结算观察和业务四桶分别保存。四桶观察数组只在 `p03.fixture.four-buckets.v1` 形状中可接受；真实 CTP 聚合持仓映射仍 Blocked。观察成功仅表示保留材料，不证明对账完成。`SettlementObservation` 只是带来源的 fixture 数量记录，不是结算单解析器、权益或费用核算器。

交易日边界存在旧风险时进入 BoundaryHalted，干净时也停在 AwaitDayEvidence。旧 CloseToday 保留原语义和桶；迟到旧日成交归入旧 epoch 并去重。M1A 没有把它改为新日 CloseYesterday 的路径，也没有自动重启报价的路径。

## 风险与资金

最坏净仓区间从已记账净仓 N 出发，所有买向 H+P+V 增加上界，所有卖向 H+P+V 降低下界；相反报价不能先净额抵销。N=2、买 3、卖 1 的区间是 [1,5]。总仓上界还包括未结清开仓量和异常 X。未知事实另置 unknown，不把有限数字宣称为完整风险。

资金以整数 fixture 单位计算。每份资源保留 order_margin、position_margin、charges；订单转持仓沿用同一个 ReservationId 与覆盖证据。同一 `external_deduction_id` 在一份资金观察中只能归属一份资源，不能覆盖两个资源。覆盖身份不能单凭“订单已存在”推定。

外部预算为 `Aext − Σ(Li−min(Li,Ci)) − buffer`；当前实现中费用包含在 Li 的 charges，且不能由保证金覆盖证明覆盖，因此没有在等式外再次重复扣费。Unknown/Excluded 的 Ci=0。独立本地预算检查 `ΣLi+buffer≤localCap`。观察带账户、交易日、position epoch、来源、币种、范围、profile 和请求区间，错误版本/范围不能换掉已有基线。

已经记账的开仓保证金保守保留，后续平仓不会凭本地计算增加外部可用资金；新查询也不清除本地资源。模型费用与真实结算费用的对齐、证明后的保证金释放及正式换锚均不在 M1A。

## 容量与异常

活动与终态订单总保留数、正常/异常成交去重表、隔离记录、外部观察、每单可比证据流和撤单动作均有配置上限；终态不回收身份。StepHarness 限制待处理输入与历史总条数，不是生产消息队列，也不证明字节级预分配。

关键证据存储满时停止新单并保留未知风险。成交表满时原成交不被覆盖，未记账成交尽量保留在隔离区；隔离区也满则累加 `evidence_loss_count`、保持 CapacityHalted，完整输入仍由调用者/StepHarness trace 保留。不存在“清空后自动恢复”。这不是 M1C 回报队列恢复资格的实现。

实际 `bad_alloc` 或算术溢出返回非成功，旧财务状态保留并停止；调用者必须保留未应用输入，M1A 无崩溃后恢复承诺。测试覆盖的是可控容量和明确预提交失败缝，不把它们等同于操作系统 OOM、磁盘失败或真实线程竞态实验。
