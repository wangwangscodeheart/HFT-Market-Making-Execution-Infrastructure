# 第三十三轮：查询准入与交付后视图对齐分离

日期：2026-11-07。

## 原缺口

原查询检查保证对端快照内部一致、订单身份能关联核心及没有遗漏已记账成交，但没有区分“可以接收这份查询”与“交付后双方订单状态确实一致”。完整快照可能显示订单已撤，而核心终态尚未入账；仅价格、数量与持仓相同不能证明订单证据已对齐。

## 两阶段检查

交付前仍检查配置/来源、查询身份、数量和预算、已知订单/成交，并新增可信累计下界不可倒退的检查。没有新成交需要处理时，不能把已知撤单/拒单终态重新解释为活动订单，不能用查询推翻明确的 NotSent。

新增只读 compare_local_query_with_core，在实际回报完成交付之后比对每笔累计已记账量、执行状态、订单一致性、活动订单待撤状态、四桶持仓与冻结。没有交付的终态或成交仍保持 Incomplete，不直接覆盖核心或凭查询结果伪造终态。

运行器只有在整批已交付、且后置检查 Complete 时，才解除本次局部 query_blocked；delivery_loss 仍独立保持。Kill、容量停报和其他核心风险状态不会被此检查解除。查询未完成或回报提交失败时不声称执行过后置核验。

每帧新增可空 query_aligned：true 表示本次交付后的模型视图一致，false 表示已核验但未对齐，null 表示该帧尚未执行后置检查。它不是恢复证书、真实账户核对通过或重新报价许可。

## 不丢弃矛盾中的经济事实

已知订单出现新的、身份有效且通过本地查询结构检查的成交时，即使它与旧终态矛盾，也不能仅凭状态差异提前拒绝整批。交付前让新经济成交进入核心；核心记账、保留冲突并停报。后置核验不能把冲突清除或显示为对齐。

新增回归先记录“撤单累计零成交”终态，再让独立对端成交一手并查询。查询准入允许交付新成交，核心返回 EvidenceConflict，但成交账本和持仓保留这一手、模式进入 ConflictHalted；后置检查不返回 Complete。

这不等于允许身份不明、缺行或已知成交数据被篡改的查询进入核心。那些仍由既有准入检查阻断。

## 验证与展示

新增七项回归覆盖可信累计未记账时查询倒退、终态不能复活、缺本地终态时前置通过但后置不对齐、实际成交交付后对齐而 Kill 保持、数量相同但订单未知仍不对齐、待交付终态重试后重新查询，以及矛盾新成交不丢弃。

页面状态条和原始观察区展示“交付后视图对齐”。既有溢出场景会同时显示视图对齐为是、交付丢失标记仍有、查询限制仍保持，明确分开数据视图与停报资格。Node 回归检查这一组合。

还增强了原对端撤单容量回归：一笔撤单未被对端接纳，双方数量/持仓和资金模型虽一致，核心仍有活动订单待撤。完整查询不产生核心调用，query_aligned=false、query_blocked=true，核心风险不释放。

中间目录 `2026-11-07-query-alignment-debug/release` 和 `2026-11-07-query-alignment-sealed-debug/release` 保留；最终目录为 `evidence-local/2026-11-07-query-alignment-final-debug`、`evidence-local/2026-11-07-query-alignment-final-release`。当前源码以最终目录为准。

## 限制

仅比较明确 LocalSim 模型的当前日已知订单/成交视图，没有真实柜台分页覆盖、会话恢复、证书或人工复位。没有新增终态查询自动归一化、清除未知订单状态或跨进程恢复能力。系统仍为有限内存、同步调用；原生浏览器布局、Linux 和真实性能尚未验证。
