# 第四十八轮：资金覆盖路径配对诊断

日期：2026-11-08。

新增 p03_funds_view_benchmark，在同一进程、同一 FundsLedger 上串行交替运行当前 view 与原嵌套算法的诊断参考实现。资源和覆盖证明各取 0、8、32、64 项，证明逆序排列并混合 Proven/Unknown/Excluded，每档预热 50 对、测量 500 对，共 4,000 次测量调用。每对比较全部资金视图字段，不以计时结果替代正确性。

两种算法各自保留 500 个原始纳秒样本、nearest-rank p50/p99、min/max。计时使用 steady_clock，不包含资源/观察构造与额外检查，不扣除计时器开销。交替调用顺序减少固定先后偏差，但仍未绑核或隔离系统负载；参考实现与生产 view 的编译/内联条件可能不同。这是算法专项对照，不是旧新完整生产程序的严格 A/B，也不是 CoreLoop 或网关延迟测试。

Node 独立检查全部分位数，并用已知构造公式核对本地需求、覆盖额、未覆盖额和外部预算。四项专项负控拒绝错误覆盖、错误分位数、参考样本缺失和网关范围误标。可执行文件和 JSON 纳入构建封存；旧两组核心诊断、业务测试和离线包检查继续运行。

零读数不能理解为零成本，短路径接近本机计时粒度。Debug 的 64 项 p50 为当前 9.8 微秒、参考 8.7 微秒，方向相反；参考实现和生产函数编译条件不同，因此本轮不作所有配置均提速的结论，也不将配对结果当作实盘性能。

Debug / Release 各 250 项业务测试、27,847 次断言，0 失败、0 跳过。每配置专项测量 4,000 次调用，四项新增专项负控通过；原有七项核心诊断负控、十二项证据负控、四项包负控及全部页面逻辑检查通过。十三份确定性业务输出在两配置间及与上一轮 Release 完全一致。计时样本各自验证，不要求逐字节相同。
