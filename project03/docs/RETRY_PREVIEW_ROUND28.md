# 第二十八轮：批量提交失败与显式重试轨迹

日期：2026-11-07。

## C++ 独立场景

新增 `p03_export_quote_runner --retry`，十步输入依次为初始双侧报价、暂扣买侧成交、暂扣卖侧成交、设置一次提交失败、查询成交并在首条核心提交时失败、队列非空时的市场输入、显式重试、查询限制仍在时的市场输入、重新完整查询、最后 Kill。

首次查询失败后，核心尚未记账，两条回报仍在队列，已知待补齐为 2；尚未尝试的第二条没有消失。重试成功后两条成交入账，队列和已知待补齐都归零，但 query_blocked 保持。此时市场输入没有产生核心调用。再次通过完整查询检查后，两条成交都返回 Duplicate，才解除该局部查询限制。

整个实验 delivery_loss 为 false，不演示解除丢失标记。局部查询限制解除不是恢复证书或真实 gate 复位。

最终核心和对端四桶均为 `1/0/1/0`。净仓为零但多今、空今各一手，总仓为两手；Kill 不会将成交持仓清零，不自动互相净掉。

导出程序执行同配置原始内存输入重放；新增 C++ 用例逐帧比较返回值、核心摘要、待交付数、已知待补齐数、查询限制和核心调用数。

## 工作台

报价轨迹页新增第四个场景“批量提交失败 / 保留 / 显式重试”。每帧显示待交付队列、查询限制、交付丢失标记，以及核心与对端四桶持仓。原有持仓读数保留，新增四桶说明防止只看净仓或单侧数量。

逐步说明区分预期故障注入、核心业务错误、显式重试及查询复核。切换场景时检查点回到首帧并更新 SHA256。页面不在浏览器里模拟成功或绕过核心决定。

## 证据流程

构建脚本封存 quote-retry.json；带 quote_retry_export 标记的运行必须包含该产物，共 29 项原始构建产物。生成脚本核验完成状态、源码/归档/产物哈希，再检查失败时两条保留、重试后仍保持查询限制、阻断帧无调用、复核成交去重、最终四桶和无丢失标记。

Node DOM 检查覆盖十帧选择、失败结果、两类队列读数、查询限制、空调用、重复成交、双向持仓、来源哈希和回到原场景；旧页面和其他轨迹回归保留。
