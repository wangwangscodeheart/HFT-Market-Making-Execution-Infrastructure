# 第三十轮：容量停报后的有界收尾路径

日期：2026-11-07。

## 修正

原 LocalQuoteRunner 在普通输入记录或核心调用预算不足时设置 stopped，随后拒绝所有输入。已有订单可能仍活动、收件箱也可能仍有未记账成交，但 Stop 和显式重试同样被拒绝。

现在正常处理与收尾各有输入/核心调用额度。普通额度不足时继续保持 stopped，禁止 MarketPulse、产生新模拟成交的 LocalFillInput、暂扣成交指令和新故障设置；仅允许 StopLocalQuotes、LocalRetryEvidenceInput、LocalHeldReportInput、LocalTradeQueryInput 和 LocalQuoteTimer 使用收尾预留额度。

其中 LocalFillInput 是驱动模拟对端产生成交的指令，不是真实网关回报入口。允许交付的是先前保留的报告或查询已有事实；本实现没有接入真实网关事件通道。

收尾额度有独立的 cleanup_inputs 和 cleanup_core_calls，默认 16 个输入与 4096 次核心调用。构造时要求每套调用额度足以预留完整单输入上界，输入记录总上限为普通额度加收尾额度。每帧 cleanup_lane 明确标记实际使用哪套额度，核心序号仍连续，运行器输入编号与核心序号仍分开。

Stop 可以在第一次发现普通额度不足时直接使用预留路径，不要求先投递一条失败的市场输入。查询或重试成功不会清除 stopped，也不重开普通报价。收尾额度耗尽返回 Capacity、保留现存状态并设置 cleanup_exhausted，不偷偷扩大队列或做无记录的核心操作。

## 异常与时间

收尾仍要求逻辑时间不倒退；被拒绝的倒退输入不占预留记录。未处理异常与普通容量停报分开：异常会设置 fatal，继续拒绝全部写操作并传播异常，不在可能不完整的组件状态上尝试收尾。已有单条核心事务保证不变，多组件/多次调用不具有整体回滚。

本轮没有增加内存分配异常注入用例，不宣称验证了 OOM 自动恢复。核心报告提交失败是明确的 StepResult 错误，和未处理异常不同；前者保留失败项，可以在收尾额度内显式重试。

## 验证

新增五项回归：普通记录耗尽后重试成交并 Stop、独立收尾调用预算与不能重开、原始输入重放选择同一收尾路径、倒退时间不消费预留记录、非法收尾容量配置拒绝。原普通输入/调用容量用例增强为验证收尾 Stop 实际撤单且留痕。

C++ 测试中的未被接纳的市场容量尝试不在业务轨迹内；重放同配置的已接纳输入仍能在容量边界选择相同收尾路径。这是本地确定性驱动规则，不是完整持久化输入审计。

导出 JSON 与页面原始观察区新增 cleanup_lane。现有五组页面案例均未消耗正常额度，仍是普通路径；本轮收尾行为由新增 C++ 组合回归验证，不把旧页面轨迹当成收尾场景的证明。

证据目录：`evidence-local/2026-11-07-cleanup-reserve-debug`、`evidence-local/2026-11-07-cleanup-reserve-release`。

## 限制

MSVC Debug / Release 各 217 项测试、26951 次断言通过，零失败/跳过。源码声明、编译注册表、聚合输出和 CTest JUnit 一致，八项证据负控与三组页面 Node 逻辑检查通过；十份既有导出诊断在两配置逐字一致。当前页面数据来自本轮 Release。

收尾容量有限，耗尽后仍可能存在未处理风险；不保证有限内存可以无限接收回报。预留是运行器的内存记录/调用预算，不是持久化权限、发送许可或恢复证书。仍无真实网关、后台线程、耐久日志、跨进程恢复、Linux 验证、原生浏览器布局验收或性能结论。
