# 第十九轮：查询缺项检查与只读订单规划

日期：2026-11-07。

## 查询检查

LocalSim 同步查询新增显式完成标记和期望订单/成交行数。`review_local_query` 只读检查账户、实际合约、交易日、模拟代次、容量、行数、订单身份、成交去重、查询来源、版本、成交量与订单累计一致性，并由初始持仓和成交独立重算四桶及平仓冻结。

检查结果分为 Complete、Incomplete 和 Invalid。Complete 仅指这一份本地同步模型快照通过结构与数量检查，不代表全账户恢复资格，不证明资金对账或真实柜台查询完备性。查询检查不接收可变核心、不释放资源、不签证书、不复位 gate。

查询先补齐场景先构造一份缺少成交行的查询，实际检查得到 Incomplete，且核心状态保持不变；随后完整查询通过才向核心交付成交。JSON 的 blocked_queries 记录这一负控，工作台在查询路径说明中展示它。

## 订单规划

新增 `plan_quotes`：输入明确作用域、策略、目标代次、会话和双侧价量，输出 SubmitOrder/RequestCancel 意图。它读取核心视图，不修改核心、不预占资金、不调用对端。调用者仍须逐笔通过 CoreLoop 的原子风控；规划成功并不等于委托可发送。

目标代次不等于调用方当前代次时拒绝。非 Ready、未知暴露、风险亏缺、缺失成交/不一致、多笔同侧活动报价时停止规划。目标买卖价相交时拒绝。价格/会话、速率及资金等最终检查仍由核心执行。

旧报价需要变更时只输出撤单；待撤/未知撤单继续占槽，不能同时建替代单。收到可信零成交撤单终态后才重新规划新单。已有相同价量报价保留。新报价优先减少反向已确认可平仓，项目配置在本切片固定为平昨优先、其次平今；没有可平仓时才开仓。一次每侧最多一个意图；若可平桶小于目标量，只规划可平部分，不跨桶拆成多笔活动报价。

当前尚无客户端请求代次持久化、自动行情输入或报价驱动循环；规划输出不具备反复执行幂等授权。调用方必须在接收订单结果后重新读取核心规划，不能重放旧计划。规划代次校验不是生产 dispatch epoch 或 Journal 发送资格。

## 验证

新增七项查询检查回归和六项规划回归，覆盖缺结束/缺行、重复/外来成交、代次与通道、持仓冻结冲突、只读性、两侧规划、先撤后建、开平路由、旧代次/kill、缺失成交、活动槽与资金拒绝。最终补充响应失败/无快照/QueryId 不匹配检查，失败响应即使带有旧快照也不能作为成功数据使用。

构建目录：`evidence-local/2026-11-07-query-planner-debug`、`evidence-local/2026-11-07-query-planner-release`。原始交接资料和历史证据不修改。

上述中间构建各 169 项、26194 次断言通过。包含最终查询响应检查及策略的合并构建，见第二十轮和 `evidence-local/2026-11-07-m1b-components-debug`、`evidence-local/2026-11-07-m1b-components-release`。
