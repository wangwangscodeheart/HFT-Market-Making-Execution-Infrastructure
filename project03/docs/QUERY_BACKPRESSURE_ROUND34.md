# 第三十四轮：失败回报期间的正常查询背压

日期：2026-11-07。

## 修正正常路径自造队列压力

原运行器已有失败回报待重试时，再执行完整查询会把同一批经济成交再次追加到收件箱。调用者为了核对而连续查询，可能把队列挤满并触发 delivery_loss；这不应成为正常查询的默认行为。

现在队列非空时，普通 LocalTradeQueryInput 返回 Blocked，保持 query_blocked，不追加报告、不自动重试、不调用核心、不减少待处理项。先由 LocalRetryEvidenceInput 显式处理已有回报，再发起完整查询，沿既有交付前/交付后检查决定局部视图是否对齐。

收尾预留路径同样执行背压，查询成功不解除普通容量停报。已有输入/调用额度仍有上限，连续查询并不获得无限记录空间。

## 显式故障注入与正常路径分开

保留原溢出实验，但新增明确的 bypass_backpressure_for_test 参数，默认 false。只有压力实验的三次追加显式设为 true，才会绕过背压，把重复报告继续压入队列。它是本地故障实验开关，不是生产策略参数或发送权限。

导出包含这个输入参数，页面说明压力注入主动绕过正常背压；生成脚本要求溢出关键帧参数为 true，Node 检查同时核对原始输入与显示文案。既有溢出停报结论保持：丢失标记不能由排空或成功查询清除。

## 验证范围

新增三项 C++ 回归：小容量模型中五次普通查询不增加失败队列、收尾路径中同样不追加并且不重开、原始输入重放保持队列和核心摘要一致。现有溢出用例明确启用压力参数，其他查询默认不变。

当前 LocalSim 查询为同进程同步快照，本轮没有实现异步旧响应、超时重连、查询身份全生命周期或分页乱序处理；没有用 QueryId 的数字大小冒充时间顺序。再次完整查询仍由核心经济成交身份去重。

首次构建因新增测试块位于辅助函数声明之前而失败，已将测试移到定义之后；失败目录 query-backpressure-debug/release 保留。最终目录为 `evidence-local/2026-11-07-query-backpressure-fixed-debug`、`evidence-local/2026-11-07-query-backpressure-fixed-release`，当前源码以最终目录为准。

系统仍为有限内存、显式驱动，不具备真实网关、线程、耐久日志或完整恢复资格。原生浏览器布局、Linux 与真实性能尚未验证。

## 最终验证结果

Debug / Release 各 231 项测试、27,203 次断言，0 失败、0 跳过。四方测试清单一致、八项证据负控通过、十二份诊断输出逐字节一致。Node 页面逻辑检查通过，最终数据来自 Release；原生浏览器布局尚未验证。
