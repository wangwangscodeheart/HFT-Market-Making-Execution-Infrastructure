# 第四十七轮：资金覆盖视图消除嵌套扫描

日期：2026-11-07。

FundsLedger::view 原先逐资源遍历全部覆盖证明。现在先单次遍历资源求本地需求，再遍历 Proven 证明并在资源表中查找对应 ID。其他状态证明跳过，资源已移除则忽略；覆盖仍取证明金额与当前资源保证金的较小值，不覆盖费用，不把资源释放作为外部可用资金增加。

工作量由资源数乘证明数的嵌套扫描改为资源遍历及证明查找；不添加缓存、不改变观察准入、证明去重、外部预算公式、强异常保证或 CoreLoop 事务。没有观察数据时仍只遍历资源一次。

新增 64 资源混合 Proven/Unknown/Excluded 对照回归，逆序覆盖证明，用原嵌套算法逐项核对资金视图。随后缩减保证金并增加费用、移除一半资源、清空资源，每阶段继续对照，确保旧证明不会虚构覆盖。另验证重复资源和算术溢出替换失败时资源、观察与视图保持。

既有 CoreLoop 状态诊断没有配置外部资金观察，因此不拿它的耗时变化作为本优化的直接性能证据。本轮结论是消除可定位的重复遍历并验证算术结果一致，不声称观测到了特定加速比例。

最终 Debug / Release 各 250 项业务测试、27,847 次断言，0 失败、0 跳过。十三份确定性场景输出在两种配置间一致，且与上一轮 Release 完全一致。七项诊断负控、十二项证据负控、四项离线包负控及主工作台/回放/八种报价场景逻辑检查通过。
