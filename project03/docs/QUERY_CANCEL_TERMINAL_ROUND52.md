# 第五十二轮：完整本地查询补齐缺失撤单终态

日期：2026-11-08。

原查询只交付成交。若本地对端已经撤单而终态回报缺失，核心仍保留可能成交量，查询最终核对会一直阻断。新增 plan_local_query_delivery：仅在 Simulator 模式且整份同步快照通过身份、计数、订单/成交对应、持仓冻结及预算重建检查后，先计划全部成交，再为缺少精确终态的 Canceled 订单计划 TerminalReport(Canceled, exact filled)。

终态来源明确为 localsim.query.orders，属于当前独立本地模拟器的查询证据，不映射为真实厂商可信 profile。不会生成 CancelReport 或伪造撤单动作成功；查询可证明订单已终结，并不证明某个请求的业务结果。对端其他状态没有被泛化为任意可恢复终态。旧 Kill、未知暴露和容量/丢失锁定不因该交付解除。

新增 LocalCancelTerminalGapInput，故意漏送下一条对端撤单终态，保留取消响应和实际对端状态。消费该故障后设置查询限制并返回 Blocked；正常报价取消过程中不会继续建立替代订单，Stop 仍尝试其他订单。该故障是显式本地实验，不是实际网关断线实现。

查询批次通过现有有界收件箱交付。成交先成功而终态提交失败时，终态保留待显式重试，后续普通查询背压生效；排空后仍需新的完整查询核对。缺行查询不交付任何事件，原订单占用不释放。完整交付后，Kill 保持，迟到成交推送去重。

新增回归覆盖无成交终态缺失、成交与终态同时缺失、终态提交失败的重试链路和逐帧重放；直接检查查询规划只读，不制造撤单动作成功，以及不完整/缺行/错误预算/账户/意图/QueryId 和 Fixture 模式均无交付计划。此轮新故障路径尚未新增独立页面场景。

最终 Debug / Release 各 261 项业务测试、28,093 次断言，0 失败、0 跳过。新增恢复、拒绝交付和重试回归通过；十三份既有确定性输出在两配置间及与上一轮 Release 逐字节一致。原有十一项诊断负控、十二项证据负控、四项离线包负控和全部页面逻辑检查通过。
