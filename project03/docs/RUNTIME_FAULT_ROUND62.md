# 第六十二轮：运行时故障进入核心有序事件

日期：2026-11-10。

新增 LocalRuntimeFault 业务事件和 RuntimeFaultState，记录故障原因位、latchVersion 与 lossGeneration。它只在显式 Simulator 模式下接受，并绑定核心 instance 与完整 BusinessScope；未知原因位、零版本、不匹配的丢失位/代次均拒绝。当前原因位对应门闩的回报丢失、Writer 故障、心跳过期、容量、计数耗尽、证据提交失败；支持记录原因不等于已实现全部故障源。

故障快照必须单调：原因只能增加，版本和丢失代次不能回退，增加原因须提高版本。完全重复返回 Duplicate；陈旧或清除已有原因的快照不覆盖状态。核心事务按既有复制/校验/swap 提交，提交失败不留下半条故障，随后同一源快照可重试。

故障归并使 Ready 进入 ConflictHalted，保留已有 Kill 和其他停机模式。回报丢失设置 unknown_exposure；原订单、风险预占、持仓、资金资源不被归零，也不伪造订单终态。核心 canonical_state 在存在故障时附加故障字段，未发生这类事件的旧场景输出保持原格式。故障状态参与事务 swap 与不变量检查。

LocalAdapterSession::sync_faults 由核心拥有者显式调用，读取共享门闩的一致快照，过滤单独的 Kill 位，再递交为一个有序 core.step。记录失败不确认源快照，下次调用重试；源与核心完全一致时不再调用核心。门闩仍负责生产者故障时立即停领，sync_faults 负责随后归并业务状态；它不是工作线程直接写核心，也没有暗中增加后台核心调用。完整 RuntimeRunner 仍需在控制调度预算中定期调用此入口。

报告队列排空或证据重试成功不会清除核心故障。即使独立查询在当前视图上对齐，也不自动解除 ConflictHalted、unknown_exposure 或发送门闩；没有新增复位授权。

新增五项回归覆盖事件边界、单调/重复/陈旧处理、确定性重放、故障事务失败与 Kill 保留，以及实际回报溢出归并后风险保留、故障记录失败重试、证据补齐后不自动复活。

范围：单一固定本地会话的故障摘要，不是完整故障历史日志或恢复证书；没有清除接口，没有多来源故障聚合、真实 Writer、SDK、TSan 或四上下文运行器。M1C 尚未完成。

最终验证：2026-11-10-runtime-fault-debug / release 干净构建均通过 317 项测试、28,686 次断言，零失败。新增五项故障回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过，十四份既有功能输出在 Debug / Release 间、与第六十一轮之间均逐字节一致。未验证 Linux、TSan 或长稳。
