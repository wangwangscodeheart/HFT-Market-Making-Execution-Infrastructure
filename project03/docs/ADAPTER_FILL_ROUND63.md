# 第六十三轮：成交经适配器线程与托管证据入账

日期：2026-11-10。

新增 simulate_fill，仅用于显式 LocalSimulator 刺激。核心拥有者复制已确认订单的 order、trade_id、quantity、price，投递到独立有界成交刺激队列；适配器线程实际执行模型成交后，才形成带经济身份的 TradeReport 并进入关键结果收件箱。该接口不是行情驱动策略或真实交易所回报入口。

成交刺激不占撤单预留槽位，也不经过新单发送 gate；Kill 不能让已接受订单的经济成交消失。未知或尚未接受的订单、无效基本字段、预算或队列容量不足在本地拒绝，不修改核心。拒绝刺激只表示模型尚未执行，不得标成“已丢失的真实成交”。每个会话成交请求默认预算 256、最多 1024，trade_id 最大 128 字节，队列默认八个槽位。

适配器每轮最多四条撤单、一条成交刺激、一条普通命令；三类命令共用唤醒信号。此优先级是本地实验调度，不能将提交刺激的先后解释为真实市场全序；例如同轮撤单优先后，模型可能拒绝已取消订单的新成交刺激。finish/析构关闭三条通道并通知，finish 排空接受任务后查询和 join。

实际成交报告使用既有 process_reports/retry_reports：提交失败不推进处理索引，保留经济事实，核心持仓不半更新；显式重试只入账一次。相同 trade_id、相同经济内容由独立对端和核心共用经济身份去重，重复交付不增加持仓、成交账本或资金占用。报告来自实际适配器线程，不通过该线程回调核心。

新增五项回归覆盖：Kill 后部分成交仍记入一手持仓、保留两手可能数量并查询对齐；成交提交失败保留并显式重试一次入账、故障保持停报；重复对端成交报告不重复记账；刺激输入校验及 Created 阶段阻断不修改核心；有限预算拒绝不生成第二笔经济成交。

边界：这是固定普通限价订单的局部成交并发路径，不代表未知/已撤订单迟到成交、完整交易回报矩阵、真实协议或全部故障恢复均已完成。核心故障仍由拥有者调度 sync_faults；没有真实 Writer/BridgeIO、SDK、恢复复位或 TSan 结论，M1C 尚未整体完成。

最终验证：2026-11-10-adapter-fill-debug / release 干净构建均通过 322 项测试、28,737 次断言，零失败。新增五项成交回归经 CTest 与聚合执行通过；证据报告、页面逻辑与离线包检查通过。Release 当前源码与 40 份产物哈希核验通过，十四份既有功能输出在 Debug / Release 间、与第六十二轮之间均逐字节一致。未验证 Linux、TSan 或长稳。
