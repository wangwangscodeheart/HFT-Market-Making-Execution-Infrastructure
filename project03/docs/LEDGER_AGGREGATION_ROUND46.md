# 第四十六轮：消除逐订单的重复成交扫描

日期：2026-11-07。

静态检查定位到两处重复遍历：RiskEngine::resources 对每个订单调用 exception_quantity，核心不变量对每个订单调用 normal_quantity。它们原先各自扫描完整成交账本，订单与成交同时增长时形成订单数乘成交数的工作量。

现在资金资源计算在一次账本遍历中汇总异常成交数量，再逐订单查找；核心不变量在原有逐成交身份/方向/持仓校验循环中同步汇总正常成交量，再与订单 booked 比较。仍使用 checked_add，资金公式、异常成交不抵扣保证金、冻结/持仓重建及证据检查均保留。临时汇总表只在当前调用存在，不增加跨事件缓存或改变事务状态/规范摘要格式。

新增独立对照回归：多笔开仓与平今订单，各自正常成交并混入超量异常成交，用原来的逐订单 normal_quantity/exception_quantity 扫描重新计算资源，逐项比较结果；异常成交查询重复交付仍不增加资金需求。另在二十笔已成交订单状态下注入提交失败，逐项检查订单分区、成交账本、持仓、资金、参考价不变，随后正常重试成功。失败尝试仍推进输入/业务序号与时间，不要求完整诊断摘要不变。

性能仍用上一轮相同八档诊断验证，另比较既有十三份确定性场景输出与上一轮原始输出。对照不是隔离主机上的 A/B 实验，不设置硬性加速阈值，不凭一次计时保证普遍收益。

## 最终验证

Debug / Release 各 248 项业务测试、27,808 次断言，0 失败、0 跳过。十三份确定性场景输出不仅在两个配置间一致，也与优化前第四十五轮 Release 原始输出逐字节一致。原有七项诊断负控、十二项证据负控、四项包负控和全部页面逻辑检查通过。

首次新增回滚测试错误地要求完整规范摘要不变，忽略失败输入仍推进序号和时间；修正为检查业务状态后重新构建。原 ledger-aggregation-debug/release 失败记录保留，最终证据为 evidence-local/2026-11-07-ledger-aggregation-fixed-debug、evidence-local/2026-11-07-ledger-aggregation-fixed-release。
